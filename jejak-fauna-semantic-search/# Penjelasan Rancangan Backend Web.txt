# **Penjelasan Rancangan Backend Web Semantik — Jejak Fauna**

**Jejak Fauna — Semantic Search Engine Fauna Langka Kalimantan**

Jejak Fauna merupakan rancangan web semantik yang berfungsi sebagai mesin pencarian untuk menemukan, menelusuri, memahami, dan memperoleh informasi mengenai fauna langka yang berada di Kalimantan, Indonesia.

Berbeda dengan website biasa yang umumnya mencari informasi berdasarkan pencocokan teks atau keyword, Jejak Fauna dirancang memanfaatkan data semantik, RDF (Resource Description Framework), ontologi, dan SPARQL untuk menghubungkan informasi fauna berdasarkan hubungan antar-data.

# **1. Gambaran keseluruhan sistem Jejak Fauna**

Secara garis besar, Jejak Fauna memiliki 4 lapisan utama.

### **1. Frontend — User Interface**

Website · Search · Filter · Detail Fauna · Graph

### **2. Backend — Laravel API**

Routes · Controller · Validation · Services · JSON

### **3. Semantic Engine**

SPARQL · RDF · Semantic Query · Relationships

### **4. Semantic Data**

Ontology · RDF/Turtle · Fauna Dataset · Relationships

Diagram konseptual arsitektur Jejak Fauna. Ini menggambarkan rancangan sistem, bukan berarti seluruh lapisan sudah selesai diimplementasikan.

| Layer           | Fungsi                                                     |
| --------------- | ---------------------------------------------------------- |
| Frontend        | Menampilkan informasi dan menerima input pengguna          |
| Backend Laravel | Mengelola request, validasi, logika aplikasi dan response  |
| Semantic Engine | Memproses query semantik dan hubungan data                 |
| Semantic Data   | Menyimpan pengetahuan fauna dan relasinya dalam bentuk RDF |

Keempat layer ini memiliki fungsi berbeda tetapi saling terhubung.

# **2. Mengapa Jejak Fauna menggunakan Web Semantik?**

Website pencarian biasa mungkin mencari fauna menggunakan nama yang dimasukkan pengguna.

Misalnya, pengguna mengetik:

> Orangutan

Sistem biasa mungkin mencari teks `orangutan` di kolom nama fauna.

Namun, Web Semantik memungkinkan sistem memahami informasi berdasarkan struktur data dan hubungan yang didefinisikan dalam dataset.

Contoh informasi semantik yang secara konseptual dapat direpresentasikan:

## **Contoh hubungan semantik**

### **Orangutan**

Subject · Resource

memiliki status konservasi

### **Critically Endangered (CR)**

Object · Value

### **Orangutan**

habitat

### **Kalimantan**

Contoh konseptual relasi semantik. Relasi dan nilai sebenarnya mengikuti dataset Jejak Fauna.

Dengan pendekatan semantik, informasi tidak hanya menjadi teks yang berdiri sendiri, tetapi dapat direpresentasikan sebagai entitas dan hubungan yang memiliki makna.

## **Perbedaan pencarian biasa dan pencarian semantik**

| Pencarian biasa                                | Pencarian semantik                                                    |
| ---------------------------------------------- | --------------------------------------------------------------------- |
| Berfokus pada keyword                          | Berfokus pada data, makna, dan relasi yang dimodelkan                 |
| Mencocokkan teks                               | Menggunakan struktur dan relasi semantik                              |
| Hasil bergantung pada pencocokan               | Hasil bergantung pada query, struktur data dan logika yang diterapkan |
| Relasi antar-informasi tidak otomatis tersedia | Relasi dapat direpresentasikan dan ditelusuri                         |
| Umumnya berbasis teks                          | Berbasis data terstruktur semantik                                    |

Web Semantik tidak otomatis berarti AI atau memahami bahasa manusia seperti ChatGPT.

Jejak Fauna memperoleh kemampuan semantik karena data, relasi, query, dan logika backend dirancang untuk memproses informasi yang memiliki struktur dan makna.

## **3.1 Laravel**

Laravel merupakan framework PHP yang digunakan untuk membangun aplikasi backend.

Dalam Jejak Fauna, Laravel bertindak sebagai penghubung antara pengguna melalui frontend dengan mesin pemrosesan semantik.

Laravel mengatur:

- Endpoint API.
- Request pengguna.
- Validasi input.
- Controller.
- Service.
- Response JSON.
- Error handling.
- Pengelolaan konfigurasi.

Laravel tidak secara otomatis memahami RDF. Kemampuan mengolah RDF dan query semantik berasal dari implementasi semantic engine yang kamu bangun dan library atau mekanisme pemrosesan yang digunakan.

## **3.2 SPARQL**

SPARQL adalah bahasa query untuk RDF.

Jika SQL digunakan untuk mengambil data dari tabel relasional, SPARQL digunakan untuk mencari informasi dari graph RDF berdasarkan pola hubungan.

Contoh konseptual SPARQL:

```
SELECT ?fauna ?status
WHERE {
    ?fauna memilikiStatusKonservasi ?status .
}
```

Contoh ilustratif. Nama predicate harus menyesuaikan vocabulary atau ontologi yang sebenarnya digunakan Jejak Fauna.

Query ini secara konseptual mencari resource fauna beserta status konservasinya melalui hubungan yang dinyatakan dalam RDF.

SPARQL dapat digunakan untuk:

- Mencari resource berdasarkan pola relasi.
- Mengambil informasi dari RDF.
- Menghubungkan beberapa informasi.
- Menelusuri graph.
- Menggunakan filter.
- Mengambil hasil query berdasarkan variabel.

## **3.3 RDF**

RDF adalah model data yang menggunakan struktur triple.

## **Struktur RDF Triple**

### **Subject**

Entitas

### **Predicate**

Relasi

### **Object**

Nilai / Entitas

Subject — Predicate — Object

Contoh:

| Elemen    | Contoh                   |
| --------- | ------------------------ |
| Subject   | Orangutan                |
| Predicate | memilikiStatusKonservasi |
| Object    | CR                       |

Satu triple dapat menyatakan satu hubungan. Beberapa triple yang saling terhubung membentuk graph pengetahuan.

## **3.4 Turtle (.ttl)**

Turtle merupakan format untuk menyimpan RDF dalam bentuk teks.

Contoh ilustratif:

```
:Orangutan :memilikiStatusKonservasi :CR .
:Orangutan :memilikiHabitat :Kalimantan .
:Orangutan :memilikiNamaIlmiah "Pongo pygmaeus" .
```

Contoh sintaks ilustratif, bukan kutipan dataset aktual.

File Turtle memungkinkan dataset semantik disimpan dalam file yang dapat dibaca dan diproses oleh semantic engine.

# **4. Perbedaan Ontologi, RDF, Turtle, dan SPARQL**

Bagian ini sangat penting karena keempatnya sering tertukar ketika mempelajari Web Semantik.

### **ONTOLOGI**

Menentukan konsep, kelas, atribut dan hubungan yang dimodelkan

### **RDF**

Merepresentasikan informasi dalam bentuk triple

### **TURTLE**

Format teks untuk menuliskan dan menyimpan RDF

### **SPARQL**

Bahasa query untuk mengambil informasi dari RDF

| Teknologi | Pertanyaan yang dijawab                             |
| --------- | --------------------------------------------------- |
| Ontologi  | Apa konsep dan hubungan yang dimiliki domain ini?   |
| RDF       | Bagaimana informasi dan hubungan direpresentasikan? |
| Turtle    | Bagaimana RDF dituliskan dalam format file teks?    |
| SPARQL    | Bagaimana informasi tersebut dicari dan diambil?    |

### **Ontologi**

Ontologi adalah model konseptual yang mendefinisikan konsep, kelas, atribut, dan hubungan dalam suatu domain.

Dalam domain Jejak Fauna, secara konseptual bisa terdapat:

- Fauna.
- Habitat.
- Status konservasi.
- Klasifikasi.
- Wilayah.
- Nama ilmiah.

Ini adalah contoh rancangan konsep, bukan klaim bahwa semua class tersebut telah didefinisikan dalam ontologi aktual project kamu.

Ontologi membantu menentukan struktur pengetahuan yang akan digunakan.

### **RDF**

RDF merupakan model representasi data yang menyatakan hubungan antar-resource.

### **Turtle**

Turtle adalah salah satu format penulisan RDF yang mudah dibaca manusia.

### **SPARQL**

SPARQL digunakan untuk mengambil informasi dari data RDF berdasarkan pola yang ditentukan.

Keempatnya saling melengkapi, bukan saling menggantikan.

## **5.2 Fungsi masing-masing komponen**

| Komponen        | Fungsi                                      |
| --------------- | ------------------------------------------- |
| Frontend        | Mengirim request dan menampilkan data       |
| API Routes      | Menentukan URL, HTTP method, dan controller |
| FaunaController | Mengatur request, validasi, dan response    |
| SparqlService   | Mengolah data/query semantik                |
| Dataset Turtle  | Sumber data fauna dalam bentuk RDF          |
| File Cache      | Mengurangi kebutuhan pemrosesan berulang    |
| JSON Response   | Mengirim hasil kepada frontend              |

### **A. API Routes**

API Routes adalah pintu masuk request dari frontend.

Misalnya frontend mengirim:

```
GET /api/fauna
```

Laravel akan mencari route yang sesuai dan meneruskannya ke controller yang ditentukan.

### **B. FaunaController**

FaunaController merupakan bagian yang menangani request API untuk fitur fauna.

Controller berperan sebagai pengatur alur request.

Secara konseptual:

1. Menerima request.
2. Membaca parameter.
3. Melakukan validasi jika diperlukan.
4. Memanggil service.
5. Mengolah hasil yang akan dikirim.
6. Mengembalikan response JSON.

Controller sebaiknya tidak menjadi tempat seluruh query semantik ditulis sekaligus. Pemisahan service membantu menjaga kode lebih terstruktur.

### **C. SparqlService**

**SparqlService merupakan komponen inti dari pekerjaan Backend Web Semantik kamu.**

Service ini berperan dalam proses pemrosesan dataset dan query semantik yang digunakan oleh fitur API.

Tanggung jawab yang dilaporkan pada implementasi ini meliputi pemrosesan dataset Turtle, pencarian semantik, filter, rekomendasi, dan data untuk knowledge graph, sesuai alur yang digunakan oleh controller.

Tujuan pemisahan service:

- Memisahkan logika pemrosesan semantik dari controller.
- Mempermudah pengembangan query.
- Mempermudah testing.
- Mengurangi kode yang berulang.
- Mempermudah pemeliharaan.

### **D. Dataset Turtle**

Dataset Turtle menjadi sumber pengetahuan fauna yang digunakan API.

Dataset yang telah diuji berisi:

# **334 fauna**

Dataset berhasil diproses oleh backend

Jumlah berdasarkan laporan pengujian terakhir, bukan audit ulang dataset pada percakapan ini.

Dataset bukan sekadar tabel nama fauna. Dataset RDF dapat menyimpan informasi dalam bentuk resource dan hubungan, tergantung struktur data yang didefinisikan.

### **E. File Cache**

Pada audit sebelumnya, ditemukan bug karena cache menggunakan konfigurasi database yang belum tersedia.

Masalah: cache default menggunakan database yang belum tersedia.

Perbaikan dilakukan dengan menggunakan cache file secara eksplisit pada SparqlService.

Sebelum perbaikan

API membutuhkan konfigurasi cache database yang menyebabkan error 500.

Setelah perbaikan

Dataset menggunakan mekanisme file cache sehingga API dapat bekerja tanpa database Laravel yang belum tersedia.

Cache tidak sama dengan dataset. Cache adalah mekanisme pendukung untuk menyimpan hasil atau data pemrosesan agar tidak perlu diproses berulang dengan cara yang sama. Dataset tetap menjadi sumber data yang digunakan sistem.

# **7. Rancangan request dan response API**

Backend Jejak Fauna menggunakan pendekatan REST-style API dengan HTTP method yang sesuai untuk operasi pengambilan data dan pengiriman input pencarian.

## **7.1 Mengapa API menggunakan JSON?**

JSON (JavaScript Object Notation) merupakan format pertukaran data antara backend dan frontend.

Contoh ilustratif:

```
{
  "nama": "Orangutan",
  "status": "Kritis",
  "habitat": "Kalimantan"
}
```

Backend mengirim data JSON. Frontend kemudian dapat mengolah data tersebut untuk menampilkan:

- Card fauna.
- Halaman detail.
- Filter.
- Search result.
- Graph.

## **Contoh komunikasi**

Frontend

Meminta informasi fauna melalui HTTP.

Backend

Memproses request, query dan data.

JSON Response

Data dikirim kembali ke frontend.

## **7.2 HTTP status code yang digunakan**

| Status code | Fungsi                | Penggunaan Jejak Fauna           |
| ----------- | --------------------- | -------------------------------- |
| 200         | OK                    | Request berhasil                 |
| 404         | Not Found             | Fauna tidak ditemukan            |
| 422         | Unprocessable Content | Input atau parameter tidak valid |

Status tersebut telah diuji dalam laporan HTTP testing terakhir.

### **Mengapa&#x20;**`422`**&#x20;penting?**

Misalnya pengguna mengirim query yang kosong atau parameter yang tidak sesuai aturan.

Backend tidak seharusnya langsung mengalami crash.

Sebaliknya, backend memberikan status `422` sebagai indikasi bahwa input yang dikirim tidak dapat diproses karena validasi.

### **Mengapa&#x20;**`404`**&#x20;penting?**

Ketika pengguna meminta detail fauna yang tidak tersedia, backend memberikan respons `404`, bukan mengembalikan detail yang salah atau menyebabkan error internal.

### **Mengapa&#x20;**`500`**&#x20;harus dihindari?**

`500 Internal Server Error` menunjukkan adanya masalah internal yang menyebabkan request gagal.

Pada audit sebelumnya, cache database menyebabkan endpoint gagal. Setelah cache file diperbaiki, pengujian terakhir tidak menemukan error `500`.

### Penjelasan Backend Jejak Fauna

Pada project Jejak Fauna, saya bertanggung jawab pada bagian Backend, khususnya implementasi API dan integrasi pemrosesan data semantik.
